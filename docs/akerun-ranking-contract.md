# Akerun verified ranking contract (v2)

## 目的

Akerunの通常プレイだけを、カメレオンJP実験場の共通ランキングへ登録する。公開のランキング表は既存の共通テーブルを使い、Akerun固有の公開テーブルは追加しない。

## プレイ開始

ブラウザは `akerun-competition` Edge Functionへ `prepare` を送り、サーバー発行の `runToken` と公式問題ID・バージョンを受け取る。続けて `begin` を呼ぶ。

- 問題IDを省略した開始は、サーバーが20問から抽選する
- 通常の新規開始で問題IDを指定しても受理しない
- 「同じ問題でもう一度」だけ、完了済み同一問題の `replayRunToken` と問題IDを提示できる
- 問題ID、問題バージョン、クライアント版、契約版はサーバー台帳と照合する
- バックグラウンド復帰は一時停止から同じ実行を続ける。再読込後は端末チェックポイントと同じ `runToken` を照合し、問題固有のstage、固定ホイール、プロトコルphase、後半アクチュエータの整合性と機構状態・計測値を復元できた場合だけ再開する。復元できない旧形式や壊れた保存データはトークンを再利用しない
- `prepare`のみ成功して`begin`の確認に失敗した場合、ブラウザは`abandon`をベストエフォートで呼び、既知のトークンを`rejected`へ遷移させてから端末内プレイへ退避する。`abandon`が通信断で届かない場合に備え、`prepared`の予約保持は開始前10分に制限し、`begin`成功後は24時間へ延長する

## 結果送信

開錠した通常プレイだけが `finish` を呼ぶ。サーバーは以下を検証する。

- `runToken` が本人の active run である
- プレイヤー名、問題ID、問題バージョンが開始時の台帳と一致する
- 経過時間、失敗数、総回転数、偽ゲート接触数の範囲が妥当である
- `begin`後のサーバー経過時間を測定し、`finish`の経過時間が1秒未満、またはサーバー測定値より3秒を超えて短い場合を拒否する
- 問題ごとの最低必要回転数未満の結果を拒否する
- 偽ゲート接触数は、問題固有の不可避な基準通過を差し引いた「余分な接触数」として送る
- 余分な回転数と観察精度を公式式から再計算する
- 基準時間、基準回転数、基準失敗数、難度補正からスコアを再計算する
- 一つの `runToken` は一度だけ共通ランキングへ書き込める
- `abandon`済みの`runToken`は`finish`できない。すでに`completed`、`expired`、`rejected`のトークンへの`abandon`は状態を変更せず、再送可能な完了記録を壊さない

公式プレイ中のRESETは、計測値を初期化する再試行ではなくリタイアとして扱う。途中からやり直す場合は、結果画面またはタイトル画面から新しいプレイを開始する。

送信失敗時は `runToken` を含む結果を端末内へ保存し、明示的な再送で同じ `finish` を再実行する。完了済みトークンを同じ payload で送る場合は、サーバーが既存結果を返し、二重の `score_runs` を作らない。

開錠を検知した時点で、結果を端末内へ先に保存し、進行中の実行記録を削除する。結果画面へ移る短い演出中にSafariが終了しても、同じ実行を途中状態として再利用せず、保存済みの結果を再送できる。

新しいv2結果は共通 `score_runs.metadata` に `source=akerun_verified_v2` と `verification=server-contract-v2` を付けて保存する。既存のv1結果は読み取り用に残し、ランキング取得ではv1/v2を同じ履歴として扱う。

## 順位

`get_akerun_ranking_v1` は共通 `game_scores` の最高スコアを基準に、同点時は失敗数、経過時間、余分な回転数、正規化名の順で並べる。各指標は最高スコアと同じ `score_runs` のメタデータから取得する。

## 第1段階の追加ガード

本PRの `20260829150000_akerun_result_guard_v1.sql` では、公式問題カタログへ問題ごとの `minimum_dial_steps` を追加し、既存の測定済み `par_dial_steps` を初期値として固定する。`finish` はこの値を下回る総回転数を受け付けない。

また、`begin` 時の `started_at` と `finish` 受信時のデータベース時刻から `server_elapsed_time_ms` を計算して保存する。クライアントの経過時間は、最低1秒かつサーバー測定値より3秒を超えて短くないことを確認する。ランキング受付と `akerun` の公開状態は、このmigrationでも無効のままにする。

これで時間0・回転0や、問題の最低経路を下回る数値は拒否できるが、攻撃者が最低回転数と時刻を合わせた偽造値を作る問題は残る。操作履歴の送信、サーバーでの決定的な再生、接続元・名前・端末単位のレート制限は次の実装段階である。

## 攻撃面と限界

ブラウザにはPublishable keyしか置かない。サービスキー専用の台帳・内部RPCは直接実行できない。古い共通 `submit_score` から `akerun` へ書き込む経路も拒否する。

v2では、正しい最短経路でも発生する偽ゲート通過を問題ごとの基準値へ含め、不可避な通過がスコアへ二重計上されないようにした。第1段階の追加ガードで、問題ごとの最低回転数とサーバー側の経過時間も検証する。この契約は、問題の再抽選、問題IDの差し替え、スコア式の改ざん、派生値の不一致、二重送信を防ぐ。クライアント側では、再開時に状態遷移と矛盾する端末チェックポイントも破棄する。ただし、悪意あるブラウザが最低回転数と時間を合わせた偽造値を作ることまでは証明しない。完全な入力トレース検証は、LockMechanismの決定的ルールをサーバー検証器へ移植する次フェーズで実装する。

## 現在の本番状態（2026-08-29 読み取り確認）

v2契約を基にした `akerun-competition` Edge Function v3は配置済みです。本番の読み取り確認では、公式問題20件、実行記録0件、ランキング記録0件で、受付と公開状態は無効でした。本PRの結果ガードmigrationはまだ本番へ適用していないため、適用後も同じ読み取り確認を行います。

- `private.akerun_competition_config.client_version = akerun-web-verified-v2`
- `private.akerun_competition_config.contract_version = akerun-play-v2`
- 公式問題カタログは20件
- Akerunの実行台帳は0件
- `public.games.is_active = false`
- `private.akerun_competition_config.accepting_runs = false`
- 受付停止中の準備処理が新しい実行記録を作らず拒否することを確認済み

## 有効化手順

公開前は安全のため次の2つを無効にする。

- `public.games.is_active = false`
- `private.akerun_competition_config.accepting_runs = false`

次の確認がすべて終わった後、管理者権限で同じ作業として両方を有効化する。

1. iPhone Safariの縦画面で、名前入力から開錠・結果表示まで確認する
2. 新規問題抽選と同じ問題の再挑戦が、問題固定を壊さず動くことを確認する
3. 正常送信、送信失敗からの再送、期限切れ、二重送信、ランキング取得を確認する
4. 訓練、お手本、リタイア、未クリアがランキングへ入らないことを確認する

有効化後に問題形状や基準値を変更する場合は、ランキング記録への影響を避けるため問題バージョンを上げる。
