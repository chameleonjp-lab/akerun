# PR5：スマートフォンのゲーム領域を分離

スマートフォンでCanvas、上部の「現在の操作」、プレイ中メニューが同じ領域へ
重なり、ダイヤルや作業台を操作できない状態を修正する。対象はプレイ画面と
訓練画面の表示・入力領域で、金庫ルール、採点、操作履歴、保存・ランキング契約
は変更しない。

## 変更内容

| 対象                     | 起きていたこと                                                                                   | 修正                                                                                               |
| ------------------------ | ------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| ゲームCanvas             | fixed inset-0 のCanvasがHUD・案内・下部6ボタンの背面まで広がり、画面要素が同じ場所に重なっていた | プレイ時は上部案内と下部メニューの間へCanvasを限定し、訓練時は訓練カードの上端までに限定           |
| スマートフォンの状態表示 | ライブパネルとCanvasの操作面が同じ高さに出て、ダイヤルの反応を覆っていた                         | プレイ中のライブパネルをモバイルでは非表示にし、時間・失敗・得点を上部の操作案内へ集約             |
| 短い縦画面               | 固定の最小描画高さでダイヤル半径が大きくなり、作業台がCanvas下端からはみ出していた               | 実寸の操作帯へ合わせて機構の最小高さを縮小し、ダイヤル・ボタン・作業台を同じレイアウト計算で収める |
| ページ操作               | ゲーム中のスクロールやオーバースクロールでタッチ座標がずれる可能性があった                       | プレイ・訓練レイヤーをoverflow:hiddenにし、overscroll-behavior:noneを適用                          |

画面の予約領域は、ノッチ・ホームインジケータ用のsafe-areaを含めて確保する。
Canvasは実際のCSS寸法を論理座標へ使うため、表示部品とタッチ判定の位置が一致する。

## iPhone Safari 手動確認

自動検査は実画素、safe-areaの実装差、Safariのジェスチャー挙動を代替しない。
実機またはSafariの同等サイズで、次を確認する。

- [ ] 390×844相当の縦画面で、上部の案内・ダイヤル・作業台・下部メニューが重ならない
- [ ] 402×874相当の縦画面で、ダイヤルの「− / +」と後半4部品を最後まで押せる
- [ ] 320×568相当の短い縦画面で、Canvasが下部メニューに隠れず、スクロールが発生しない
- [ ] 訓練画面で、訓練カードのボタンは押せ、カード背面の作業台も操作できる
- [ ] ノッチ側・ホームインジケータ側に文字やボタンが入り込まない
- [ ] ダイヤル操作中にページスクロール、長押し選択、拡大が発生しない
- [ ] 縦横回転後も、表示された部品と指の位置が一致する
- [ ] 通常サイズの縦画面で、時間・失敗・得点が上部の操作案内から確認できる

ブラウザ自動操作環境がない場合、上記は未確認として扱い、Draft PRのまま公開
判定へ進めない。
