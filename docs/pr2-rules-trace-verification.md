# PR2 回転・停止・記録の検証

対象: `fix/akerun-audit-pr2-rules-trace-contract`

PR2では、通過の意味をブラウザのイベント終端から切り離し、共有 `LockMechanism`・操作履歴の再生・保存先の契約を同じ条件へそろえた。

## 実装した契約

- 正規ゲートへ触れた時点では通過を確定しない。目標位置で `160ms` 動きがない状態を `tick` が確認したとき、一回だけ通過を確定する。
- 二回目以降の同じゲートは、前回確定から正しい方向へ100目盛りの実効回転を必要とする。逆方向1目盛りと正方向1目盛りの往復は周回に含めない。
- 操作履歴は既存の時刻付き `RunTrace` 形式を使い、イベント間の時刻差を停止待ちへ渡す。1・8目盛りの通知で同じ経路と停止時刻を再生し、同じ回転数・失敗・偽ゲート接触・スコアになることを検査した。
- 途中保存には一周累積数と停止確認の経過時間も含め、保存直前と同じ判定を再開後へ引き継ぐ。旧チェックポイントで値がない場合は安全側の0から再観察する。
- ルール意味の変更を旧クライアントと混ぜないため、採点式V3を維持したまま送信・保存契約を `akerun-web-verified-v4` / `akerun-play-v4` へ更新した。migration適用後も受付は無効のままにする。
- 標準以上の隠し難度では、観測メモのカテゴリを内部の偽ゲート分類から `contact` へ変換し、正規・偽のラベルや隠れた数値を記録しない。問題ID、問題版、輪、目盛り、方向、通過回数、見えている反応種別を保存する。旧形式のメモは各項目を `null` として表示できる。
