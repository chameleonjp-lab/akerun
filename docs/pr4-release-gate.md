# PR4：公開前リリースゲート

PR3までで、短い横画面でもCanvasと入力座標がずれにくくなり、
「現在の操作」を読めるようにした。PR4では、公開成果物を自動検査し、
iPhone Safariでしか分からない項目を人が同じ順番で確認できるようにする。
ルール、採点、操作履歴、保存・ランキング契約は変更しない。

## 自動ゲート

`pnpm verify:release` は `dist/public` に対して次を確認する。

- 日本語ページ、ゲーム名、説明、テーマ色、Reactの描画先が残っている
- 実寸表示とsafe areaに必要な `viewport-fit=cover` が入っている
- Viteの開発用パス、未置換の環境値、不要な内部サービス名が公開物へ残っていない
- ビルド済みJavaScriptとCSS、ゲームの「現在の操作」、プレイ中メニュー、ビルド識別子がある
- モバイルボタンの44px基準、Safariの誤ジェスチャー抑制、長押し選択抑制がある

この検査は、ブラウザを起動しなくても壊れた公開物を検出する。GitHub Actionsの品質検査とPages公開検査の両方で実行する。

## iPhone 17 Pro Safari 手動確認

実機では、次の順番で確認する。画面録画や外部サービスへの入力は不要で、各項目を満たせばチェックを付ける。

### 画面サイズ

- [ ] 縦画面（390×844相当）でタイトル、名前入力、開始ボタンが切れない
- [ ] 縦画面（402×874相当）でプレイ中の行動表示、ダイヤル、作業台、メニューが重ならない
- [ ] 横画面（874×402相当）でダイヤルと機構が下端から切れない
- [ ] 横画面の6個のメニューが一列に並び、各ボタンを指で押せる
- [ ] ノッチ側の余白に文字やボタンが入り込まない

### 1プレイの流れ

- [ ] 初回起動で訓練1から始まり、戻る・再開で同じ画面へ戻れる
- [ ] `AKERUN-01/02` では導入用の目標が表示され、`AKERUN-03` 以降とブラインドでは目標を表示しない
- [ ] ダイヤルを右回り・左回りへ切り替えても、表示された方向と実際の輪の動きが一致する
- [ ] 正規ゲートで指を止めたときだけ停止確認が進み、通過回数が一度だけ増える
- [ ] 後半のテンション、フェンス、ロックボルト、扉ハンドルを最後まで操作できる
- [ ] 開錠後に結果画面へ移り、時間・失敗・回転・偽ゲート接触・スコアが表示される

### Safari固有の安全確認

- [ ] ダイヤル操作中に長押しメニュー、ページ選択、拡大が起きない
- [ ] 指を画面外へ移す、通知でSafariを一時的に隠す、向きを変える操作で、入力が stuck にならない
- [ ] `pointercancel` 後にダイヤルや部品が勝手に動き続けない
- [ ] 音OFFでも画面の反応だけでプレイでき、振動非対応でも開錠できる
- [ ] 低モーション・高コントラストを有効にしても、行動表示とボタンが読める

### 保存と公開状態

- [ ] プレイ中にSafariを再読み込みし、途中保存から再開できる
- [ ] 開錠直後にSafariを閉じても、結果が端末に残り、結果画面から再送できる
- [ ] 公開画面の `BUILD / <12文字>` と、公開対象コミットが一致する
- [ ] ランキング受付を有効化する前に、Supabaseの版、受付停止、件数0、旧記録の隔離を管理者が確認する

## 判定と記録

自動ゲートが一つでも失敗した場合は公開しない。手動確認で一つでも再現する不具合があれば、画面サイズ、操作、再現手順を記録し、修正後に同じ項目を再確認する。

手動確認を完了できない場合、その項目は「合格」とみなさない。特にSafari実機の表示と保存復帰は、自動検査だけでは保証できない。
